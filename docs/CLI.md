# Справочник команд и флагов

Документ описывает текущее поведение пяти команд. Примеры запускаются из корня репозитория.

## Сборка

`make build` собирает пять исполняемых файлов: `bin/parse`, `bin/categorize`, `bin/enrich` `bin/geography` и `bin/export`. Нужны Go из `go.mod` и C-компилятор; сборка включает CGO для SQLite. Каталог `bin/` исключён из Git.

После сборки вместо `go run ./cmd/parse --sources all` можно запускать `./bin/parse --sources all`; аналогично для остальных команд. Флаги одинаковые. Запускайте из корня репозитория, чтобы относительные пути к БД, справочнику и файлам оставались прежними.

## Какую команду выбрать

| Задача | Команда | Что изменяет |
|---|---|---|
| Собрать компании с сайтов, назначить категории и найти руководителей | `go run ./cmd/parse` | SQLite, скачанные файлы в `prices/` |
| Пересчитать категории по уже сохранённым товарам и файлам | `go run ./cmd/categorize --db data.db --limit 0` | Категории и кеш извлечения в SQLite, отчёты |
| Проверить подбор категорий по Excel | `go run ./cmd/categorize --input companies.xlsx` | Только отчёты |
| Найти или обновить руководителей уже сохранённых компаний | `go run ./cmd/enrich` | SQLite, JSON-отчёт |
| Определить российские компании по сохранённым данным | `go run ./cmd/geography` | `is_russian` в SQLite, JSON-отчёт |
| Получить Excel из текущего состояния БД | `go run ./cmd/export` | Выходной Excel |

`parse` не создаёт Excel автоматически. `export` не запускает парсинг, поиск руководителей или категоризацию.

## Общие правила

- `--help` или `-h` показывает встроенную справку выбранной команды без её выполнения: `go run ./cmd/parse --help`.
- Один и два дефиса равнозначны: `-db data.db` и `--db data.db`. Для значений допустимо `--db=data.db`.
- Булевы флаги включаются без значения: `--force`, `--dry-run`. Для отключения используйте `--force=false`, а не `--force false`.
- Пути считаются относительно **текущей рабочей директории**, а не расположения исполняемого файла. Пути с пробелами заключайте в кавычки.
- Позиционные аргументы не используются. Указывайте всё флагами: стандартный Go-парсер прекращает разбирать флаги после первого позиционного аргумента.
- Флаги действуют только в своей команде. Например, `parse --limit 5` и `export --sources all` завершатся ошибкой неизвестного флага.
- Временные интервалы задаются как `500ms`, `2s`, `30m`, `24h`, `720h`. Запись `30d` не поддерживается.
- Существующие отчёты и Excel по указанному выходному пути перезаписываются. Для сохранения предыдущего результата задайте другой `--out`.

### Подготовка базы и зависимостей

Перед обновлением схемы существующей БД сделайте бэкап. Примените все миграции:

```bash
make migrate-up
# Если команды будут работать с другой БД:
make migrate-up DB_URL=sqlite3://./other.db
```

`--db other.db` не переключает БД в Makefile и не применяет миграции автоматически. По умолчанию Makefile использует `data.db`. При ошибке пути `parse`, `categorize` и `export` могут создать пустую БД и затем завершиться ошибкой схемы; `enrich` проверяет существование файла заранее.

Нужны Go из `go.mod`, CGO и C-компилятор для SQLite. Для чтения `.xls` нужен `libreoffice`, для текстовых PDF — `pdftotext`. XLSX и CSV читаются непосредственно программой; сканы не распознаются.

### Ключ DaData

`DADATA_API_KEY` — переменная окружения, а не флаг. Файл `.env` автоматически не читается. В Bash можно задать ключ без записи его значения в историю:

```bash
read -rsp 'DaData API key: ' DADATA_API_KEY
export DADATA_API_KEY
```

Без ключа `parse` продолжает сбор и категоризацию, сообщая об отключённом поиске руководителей. `enrich` без ключа завершается ошибкой, кроме режима `--dry-run`.

## `parse`: сбор и автоматическое обогащение

```bash
go run ./cmd/parse [флаги]
```

| Флаг | По умолчанию | Действие |
|---|---|---|
| `--sources` | `yopt` | Источники: `yopt`, `productcenter`, `yopt,productcenter` или `all` |
| `--db` | `data.db` | SQLite для чтения и записи |
| `--force` | `false` | Обновлять уже существующие компании и прайсы с сайта; новые также добавлять |
| `--downloads-only` | `false` | Скачать недостающие/пустые файлы по ссылкам из БД, затем пересчитать категории затронутых компаний |
| `--categories` | `category-normal` | Файл справочника конечных категорий, по одной на строку |
| `--aliases` | `config/category-aliases.json` | Словарь синонимов; `--aliases=''` отключает его и оставляет сопоставление по названиям категорий |

### Режимы и ограничения

- **`--force` и `--downloads-only` несовместимы.** Программа завершается до запуска обработки.
- Без `--force` существующая компания не перезаписывается данными сайта, но для встреченной компании выполняется обогащение по сохранённым данным БД. Обход сайта при этом всё равно происходит.
- С `--force` обновляются данные сайта и загружаются обнаруженные файловые прайсы. При неудачной загрузке прежний файл сохраняется. Этот флаг **не сбрасывает кеш DaData или извлечения товаров из файлов**.
- При обычном обходе категории назначаются после сохранения компании, затем пересчитываются после загрузки её файлов. Поиск руководителя выполняется при наличии ключа.
- `--downloads-only` не обходит карточки компаний и не вызывает DaData. Он может обращаться к сайтам для скачивания файлов. Категории пересчитываются после успешной дозагрузки; если дозагружать нечего, массового пересчёта нет — для него используйте `categorize --db`.
- `--categories` и `--aliases` нужны также в режиме `--downloads-only`. Названия категорий в словаре должны существовать в выбранном справочнике; иначе запуск завершится ошибкой.
- В `--sources` используйте либо `all`, либо список названий, а не `all,yopt`. Не повторяйте источник: дедупликации списка нет.
- Флагов `--limit`, `--out`, `--dry-run`, `--delay`, `--timeout` у парсера нет.

### Что сейчас задано в коде, а не флагами

Автоматический поиск DaData использует кеш 30 дней, паузу после ошибки 1 час, паузу между запросами 1 секунду и HTTP-таймаут 20 секунд. Настроить эти значения можно в отдельном `enrich`, но его флаги не меняют последующие запуски `parse`.

У ProductCenter отдельная задержка между запросами; `enrich --delay` на неё не влияет. Загрузка одного прайса ограничена 5 минутами. Каталог загрузок — `prices/`; отдельного флага для него нет. При запуске парсер также очищает старые временные и пустые файлы загрузчика.

## `categorize`: категории из SQLite или Excel

```bash
go run ./cmd/categorize [флаги]
```

| Флаг | По умолчанию | Действие |
|---|---|---|
| `--db` | пусто | Непустой путь включает режим SQLite с сохранением категорий |
| `--input` | `companies.xlsx` | Входной Excel в режиме без `--db` |
| `--categories` | `category-normal` | Справочник конечных категорий |
| `--aliases` | `config/category-aliases.json` | Словарь; `--aliases=''` отключает синонимы |
| `--limit` | `5` | Число компаний; **0 допустим только для SQLite** и означает все активные компании |
| `--out` | `outputs/category-preview` | **Каталог**, в котором создаются `report.json` и `report.md` |

### Режимы и ограничения

- **Если переданы `--db` и `--input`, побеждает `--db`; `--input` молча игнорируется.** Это не ошибка CLI, но указывать оба обычно незачем. `--db=''` возвращает режим Excel.
- В SQLite берутся активные компании обоих источников в порядке ID. `--limit` ограничивает число компаний, а не товаров или файлов. Флага фильтра по источнику здесь нет.
- В SQLite объединяются inline-товары и товары из уже скачанных файлов; команда ничего не скачивает. Результат перезаписывает `company.category_normal_json`, обновляется кеш извлечения файлов. Поэтому режим `--db` не является пробным запуском.
- В Excel берутся первые `--limit` непустых компаний в порядке листа «Компании». Требуются листы «Компании» и «Товары». Товары связываются по названию компании и ИНН; неоднозначные связи пропускаются с предупреждением. Файлы прайсов из Excel не открываются. Исходный Excel и БД не меняются.
- `--limit 0` в режиме Excel и отрицательный `--limit` в любом режиме — ошибка. Для всего Excel укажите положительный лимит не меньше числа компаний.
- **Даже с `--db` лимит по умолчанию равен 5.** Для всей БД обязательно укажите `--limit 0`.
- `--out` принимает каталог, не имя JSON-файла. Если передать `--out result.json`, программа создаст каталог с таким названием.
- Флагов `--force`, `--dry-run` и `--sources` нет. Категории пересчитываются при каждом запуске; неизменённые файлы читаются из кеша извлечения. Кеш инвалидируется по содержимому файла и версии извлекателя.

## `enrich`: поиск руководителей

```bash
go run ./cmd/enrich [флаги]
```

| Флаг | По умолчанию | Действие |
|---|---|---|
| `--db` | `data.db` | Существующая SQLite-база |
| `--sources` | `all` | `all`, `yopt`, `productcenter` или список через запятую |
| `--limit` | `0` | Максимум выбранных компаний; 0 — все активные |
| `--force` | `false` | Обойти срок кеша и паузу после предыдущей ошибки |
| `--dry-run` | `false` | Проверить ИНН/ОГРН без запросов API и записи в БД; JSON-отчёт всё равно создаётся |
| `--ttl` | `720h` | Срок использования сохранённого ответа DaData, включая ответ «не найдено» |
| `--retry-after` | `1h` | Когда после сохранённой ошибки разрешён следующий запрос |
| `--delay` | `1s` | Пауза после запроса перед следующим запросом API |
| `--timeout` | `20s` | Таймаут одного HTTP-запроса DaData |
| `--out` | `outputs/leadership/report.json` | **Путь JSON-файла**, родительский каталог создаётся автоматически |

### Совместимость и кеш

- `--limit >= 0`, `--ttl > 0`, `--retry-after > 0`, `--delay >= 0`. При реальном поиске также требуется `--timeout > 0`.
- **`--force --dry-run` разрешены вместе**, но при `--dry-run` запросов и обновления кеша нет, поэтому `--force` ничего не меняет.
- При `--dry-run` значения `--ttl`, `--retry-after` и `--delay` всё равно проверяются, но не влияют на результат. `--timeout` не используется и его положительность в этом режиме не проверяется.
- При `--force` TTL и пауза после ошибки обходятся, но задержка между запросами и HTTP-таймаут сохраняются. Один поисковый реквизит не запрашивается повторно внутри запуска даже с `--force`.
- `--retry-after` не запускает таймер повторов. После ошибки команда не ждёт час, чтобы повторить её: новые попытки возможны при последующей обработке после истечения паузы.
- `--delay 0` технически допустим. Он не изменяет ограничения внешнего API и не влияет на запросы парсера к сайтам.
- `--limit` применяется к компаниям после фильтра по источнику в порядке ID. Это не лимит запросов: кеш, одинаковые реквизиты и невалидные ИНН/ОГРН уменьшают число запросов. Это также не отбор только компаний без руководителя.
- `all` используйте отдельно, не внутри списка. Пустое значение `--sources=''` — ошибка.
- Если ИНН некорректен, используется корректный ОГРН/ОГРНИП. Поиск по названию не выполняется.
- HTTP 401/403/429 останавливают поиск с частичным отчётом; остальные ошибки отдельных запросов сохраняются, обработка продолжается. При ошибке API ранее найденные сведения сохраняются и могут быть устаревшими.

## `geography`: определение российских компаний

```bash
go run ./cmd/geography --db data.db
```

Единственный флаг — `--db` (по умолчанию `data.db`); файл должен существовать, требуется миграция 000007. Обрабатываются все активные компании обоих источников. Сайты и API не вызываются. Запуск повторяемый: решения пересчитываются по текущим сохранённым данным.

`company.is_russian`: `1` — определена как российская, `0` — явно указана иностранная страна без противоречий, `NULL` — недостаточно данных или противоречие. Основания: совпадающий ответ DaData для юрлица/ИП; пара ИНН и ОГРН с корректными контрольными цифрами и согласованным типом; явное название страны в адресе. Проверка формата пары реквизитов — эвристика, она не подтверждает запись в реестре. Один ИНН, телефон, домен или название города сами по себе недостаточны. Список распознаваемых иностранных стран ограничен; неизвестные формулировки могут остаться неопределёнными.

Отчёт с причиной каждого решения перезаписывается в `outputs/geography/report.json` рядом с выбранной БД. Неопределённые случаи можно проверить по этому отчёту. Данные компаний не удаляются.

После нового парсинга или обновления DaData запускайте механизм перед экспортом. Новые компании имеют `NULL`; изменение ИНН, ОГРН или адреса при парсинге сбрасывает старое решение в `NULL`. При обновлении только данных DaData решение обновляется следующим запуском `geography`.

## `export`: выгрузка Excel

```bash
go run ./cmd/export [флаги]
```

| Флаг | По умолчанию | Действие |
|---|---|---|
| `--db` | `data.db` | База с результатами предыдущих этапов |
| `--out` | `companies.xlsx` | Путь выходного Excel; родительский каталог должен существовать |
| `--source` | пусто | Один источник: `yopt` или `productcenter`; пусто — все |

- Все три флага совместимы.
- Здесь **`--source` в единственном числе**. Списки и значение `all` не поддерживаются: это буквальный фильтр по значению в БД. Например, `--source all` обычно даст пустые листы, а не все источники.
- Официальное название берётся из сохранённых данных DaData при совпадении реквизитов; если название там пустое — из `company.official_name`, иначе ячейка остаётся пустой. Обычное `company.name` для этого столбца не используется.
- На всех трёх листах экспортирует только активные компании с `is_russian = 1`. Иностранные и неопределённые исключены; дополнительных флагов для этого нет. Перед экспортом выполните `geography`. Категории и руководители берутся из БД; пустые значения не заполняются на лету.
- Листы: «Компании», «Прайс-листы», «Товары». Последний пока содержит только inline-товары. Товары из файлов доступны в отчёте категоризации и кеше SQLite; нормальные категории в Excel учитывают и их.
- Флагов `--force`, `--limit`, `--categories`, `--aliases` здесь нет.

## Краткая таблица спорных сочетаний

| Команда и сочетание | Результат |
|---|---|
| `parse --force --downloads-only` | Ошибка, запуск запрещён |
| `parse --downloads-only --aliases=''` | Разрешено; после дозагрузки категории подбираются без синонимов |
| `parse --force` | Обновляет данные сайта, не заставляет DaData обходить кеш |
| `enrich --force` | Обходит кеш DaData, не обновляет карточки на сайтах |
| `enrich --force --dry-run` | Разрешено; только проверка реквизитов и отчёт |
| `categorize --db data.db --input old.xlsx` | SQLite; `old.xlsx` игнорируется |
| `categorize --db data.db --limit 0` | Все активные компании БД |
| `categorize --input companies.xlsx --limit 0` | Ошибка |
| `export --source all` | Буквальный фильтр `source = 'all'`, обычно пустой результат |

## Готовые сценарии

### Обычный запуск с получением Excel

При необходимости сначала задайте `DADATA_API_KEY`, как показано выше.

```bash
go run ./cmd/parse --sources all --db data.db
go run ./cmd/geography --db data.db
go run ./cmd/export --db data.db --out companies.xlsx
```

### Полностью обновить ProductCenter, включая сведения DaData

```bash
go run ./cmd/parse --sources productcenter --db data.db --force
go run ./cmd/enrich --sources productcenter --db data.db --force
go run ./cmd/geography --db data.db
go run ./cmd/export --source productcenter --db data.db --out productcenter.xlsx
```

Первый шаг использует обычный кеш DaData, второй принудительно обновляет сведения для всех активных компаний ProductCenter в БД, включая не встреченные при последнем обходе. Если первый шаг уже сделал свежий запрос, второй может повторить его.

### Дозагрузить прайсы, затем пересчитать всю БД

```bash
go run ./cmd/parse --sources all --db data.db --downloads-only
go run ./cmd/categorize --db data.db --limit 0 --out outputs/category-files
go run ./cmd/geography --db data.db
go run ./cmd/export --db data.db --out companies.xlsx
```

### Проверить словарь на пяти компаниях без изменения БД

```bash
go run ./cmd/categorize --input companies.xlsx --limit 5 --out outputs/category-check
```

Если нужны также товары из файлов, используйте режим SQLite на отдельной резервной копии БД; флага `--dry-run` у категоризации нет.

### Проверить реквизиты, затем обновить руководителей с большей паузой

```bash
go run ./cmd/enrich --dry-run --limit 5 --out outputs/leadership/check.json
go run ./cmd/enrich --limit 5 --delay 3s --timeout 30s --out outputs/leadership/result.json
```

Первый запуск не требует ключа. Второй требует `DADATA_API_KEY` и может использовать кеш. Для принудительных запросов во втором запуске добавьте `--force`.
